Compositor Scroll Mechanics

Above this header is a 100vh transparent spacer. When you scroll or drag down at the top, the browser's compositor thread handles the scroll natively. On scrollend, if displacement is > 30%, the overlay completely closes; if ≤ 30%, CSS Scroll Snap springs it back!

1. Why Compositor Scrolling Outperforms JS Derivation

When web applications manually intercept touchstart and touchmove with non-passive event listeners, every touch packet is forced to hop from the browser's input router onto the JavaScript main thread. If the main thread experiences heavy garbage collection or layout reflows, input latency immediately degrades.

By creating a native scroller with a transparent spacer above the header, Chromium's compositor thread (cc::InputHandler) handles the gesture at 120Hz completely off the main thread.

2. Native CSS Scroll Snap Alignment

The sheet element is configured with scroll-snap-align: start. When the user releases after pulling down into the transparent spacer, if the displacement is below 30%, the compositor's native snap algorithm restores the scroller back to the 100vh position without requiring manual spring math in JavaScript.

/* Native Compositor Configuration */ .overlay-scroller { scroll-snap-type: y mandatory; overscroll-behavior-y: contain; } .overlay-sheet { scroll-snap-align: start; scroll-snap-stop: always; }

3. Listening to Offset & The 30% Threshold

The website simply queries the scroll offset of the compositor scroller. As the user scrolls into the transparent spacer:

const displacement = spacerHeight - scroller.scrollTop; if (displacement >= spacerHeight * 0.30) { // On scrollend: Dismiss overlay completely closeOverlay(); }
